# Replace the experimental plugin without backward compatibility

The existing plugin is a throwaway experiment, and preserving its memory-overlay model would add a second provider mode, storage API, CLI, and migration workflow to the homeserver-backed agent design. Build one replacement in the same repository; reuse useful SDK/build code, but permit rewriting or removing any implementation, export, command, schema, or obsolete test. Do not add old-format readers, migration commands, dual writes, fallback modes, or deprecated aliases. Old user data remains untouched and unsupported, not automatically deleted. A fresh agent is the default; an explicit one-time import from the pinned native Hermes layout is an onboarding feature, not an old-plugin migration. The fixed new namespace isolates the replacement's files, while the pinned Hermes integration and new product's durability/security acceptance tests remain required.
